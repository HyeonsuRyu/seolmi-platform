# 초원(Chowon) — 우설 유통·판매 플랫폼

소 우설(牛舌) 유통부터 판매까지 잇는 3면 플랫폼.

> **이 저장소의 범위**: CS 챗봇만이 아니라 플랫폼 전체(B2B · B2C · 관리자)를 담는다.
> CS 챗봇은 그중 `app/domains/cs/` 모듈 하나다. 저장소 이름의 `chatbot` 은 초기 명명이며
> `chowon-platform` 으로 변경 예정 (→ 7장).

> ⚠️ **현재 단계: 설계 문서만 확정된 상태.**
> 3장 폴더 구조와 4장 실행 방법은 **목표 구성**이며 아직 구현 코드는 없다.

**표기 약속** — 이 문서 전체에 적용한다.

| 표기 | 뜻 |
|---|---|
| 표기 없음 | 확정된 사실 |
| (추정) | 팀 판단. 근거는 있으나 확정 아님 |
| [확인 필요] | 외부 확인이나 담당자 확정이 필요함. 7장에 모아 둔다 |

## 1. 무엇을 만드는가

| 면 | 사용자 | 핵심 기능 |
|---|---|---|
| **B2B** | 식당 · 정육점 | 단가표, 대량·정기 발주, 규격(두께·손질 상태) 지정, 납기 확인, 세금계산서 |
| **B2C** | 일반 소비자 | 소분 상품 구매, 손질·조리 가이드, 후기, 재구매 |
| **관리자** | 초원 운영팀 | 재고·입출고, 개체 이력 관리, 주문·정산, CS 티켓 라우팅, 매출 대시보드 |

네이버 스마트스토어는 **B2C 유입 채널로만** 병행한다.
B2B·관리자 기능은 스마트스토어에 넣지 않는다 (스마트스토어가 지원하지 않음).

**B2C 핵심 타겟 2종** — 화면 순서와 콘텐츠 우선순위의 기준이다.

1. 고기는 좋아하지만 우설을 먹어본 적 없는 사람 → 진입장벽 낮추기(맛·식감·먹는 법)를 먼저 보여준다.
2. 일본에서 규탄(牛タン)을 먹고 한국에서 찾는 사람 → 규격·부위 설명과 재구매 동선을 먼저 보여준다.

## 2. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 언어 | Python 3.12+ | |
| 웹 프레임워크 | FastAPI + Uvicorn | |
| DB | PostgreSQL 16 (로컬 개발 SQLite) | 개체 이력·주문·정산 |
| ORM / 마이그레이션 | SQLAlchemy 2.x + Alembic | |

| 프론트엔드 | 1단계 Jinja2 서버 렌더링 (추정) | 이후 분리 여부는 미정 |
| 결제 | PG 연동 [확인 필요] | 축산물 온라인 판매 요건 확인 후 결정 |
| 배포 | Docker Compose (추정) | |

## 4. 실행 방법 (목표 구성)

```bash
git clone https://github.com/HyeonsuRyu/chowon-chatbot.git
cd chowon-chatbot

python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

cp .env.example .env        # LLM API 키, DB URL, JWT 시크릿 입력
alembic upgrade head
uvicorn app.main:app --reload
```

API 문서: http://localhost:8000/docs
`.env` 는 절대 커밋하지 않는다.

저장소 이름을 `chowon-platform` 으로 바꾸면 위 두 줄의 `chowon-chatbot` 도 함께 바꾼다.
GitHub가 옛 URL을 리다이렉트하므로, 이미 클론한 사람은 `git remote set-url origin <새 URL>` 한 줄로 끝난다.

## 5. CS 부서 라우팅 규칙

### 5.1 부서 정의

| 부서 | 맡는 문의 | 판정 기준 | 대표 예시 |
|---|---|---|---|
| **환불·교환** | 이미 결제된 주문의 문제 | 주문번호가 있고, 상품 상태·배송 결과에 대한 이의·반품·교환 요구 | "포장이 터져서 왔어요" / "취소하고 싶어요" |
| **마케팅** | 판매·제휴 성격의 구매 전 문의 | 대량 납품, 제휴·입점, 협찬·체험단, B2B 견적 | "식당인데 정기 납품 단가 알 수 있을까요" |
| **일반문의** | 나머지 전부 | 위 둘에 해당하지 않는 상품·배송·조리·계정 문의 | "우설 어떻게 손질해요?" / "냉장인가요 냉동인가요" |

부서 정의는 (추정)이며 운영팀 확정 필요.

### 5.2 판정 순서 — 둘 이상 걸리면 위쪽이 이긴다

1. **안전·위생** → 부서 배정하지 않고 즉시 사람에게 넘김
2. 환불·교환
3. 마케팅
4. 일반문의

### 5.3 즉시 에스컬레이션 (자동응답 금지)

- 이물질, 복통·식중독 등 건강 이상 호소
- 등급·원산지 표기에 대한 이의 제기 → 법적 리스크. 정해진 스크립트 외 답변 금지
- 언론·기관·변호사 언급
- 같은 고객이 3회 이상 재문의

### 5.4 응답 형식

CS 응답은 항상 세 블록으로 낸다.

```
[배정 부서]        환불·교환
[답변 초안]        ...
[에스컬레이션 조건] 해당 없음 / (해당 시 사유)
```

애매한 경우 부서는 하나로 단정하되, 판단 근거를 한 줄 남긴다.

### 5.5 정답셋

`tests/cs/routing_cases.yaml` 에 문의 원문과 정답 부서를 쌓는다.
캠퍼스 실습에서 사람이 라벨링한 문의 8건이 출발점이며,
CoT(단계별 사고) 유무 비교 결과도 여기서 회귀 테스트로 유지한다.
프롬프트를 고칠 때마다 이 케이스를 돌려 정확도가 떨어지지 않았는지 확인한다.

## 6. 표기 규칙 (법적 — 반드시 지킨다)

- 부위에 등급을 붙이지 않는다. "투플러스 우설", "1++ 우설" 금지.
  소 등급은 도체 단위 판정이며 부산물인 우설은 등급 판정 대상이 아니다.
- 허용 형태: "1++ 판정을 받은 한우 암소 개체에서 분리한 우설 (개체식별번호 공개)".
  등급판정확인서와 축산물이력번호가 있는 개체에 한한다.
  이 표현의 실제 허용 범위 자체도 [확인 필요] — 축산물품질평가원, 표시광고 자문.
- 등급보다 검증 가능한 근거를 앞세운다:
  개체 이력 공개 / 도축~발송 경과일 / 껍질 손질 방식 / 냉장·냉동 유지 온도.
- 한우 암소로 소구하면 수입 우설을 섞을 수 없다. 원가·물량 계획의 전제다.
- 한글 부위명은 '우설'로 통일. '소혀' 금지. 영문은 "beef tongue", 일본식 명칭은 '규탄(牛タン)' 병기 가능.
- 부정 연상어 금지: "기름지다" 류. 근거 없는 최상급 금지: "국내 1위", "최저가".
- 오픈 전이므로 후기·판매량·평점을 만들어 쓰지 않는다. 실제 후기 30건 확보 후 인용형으로 전환한다.

위 규칙은 카피·상세페이지·CS 답변·프롬프트 모두에 적용된다.
`prompts/` 안의 답변 프롬프트에도 같은 문장으로 넣어 둔다.

## 8. 팀과 역할

HYUNDAI AI Insight Campus 5조

| 팀원 | 역할 | 담당 경로 | 주 산출물 |
|---|---|---|---|
| **류현수** | 개발 리드 (백엔드) | `app/`, `pyproject.toml`, 저장소 운영 | DB 스키마·마이그레이션, 도메인 구현, 코드 리뷰 승인 |
| **조윤빈** | 팀장 · LLM/CS 파트 | `prompts/`, `app/domains/cs/`, `tests/cs/` | 라우팅 프롬프트, LLM 연동, 매입~배송 프로세스 설계 |
| **박경환** | 도메인 오너 (B2B · 사업모델) | `docs/domain-model.md`, `app/domains/pricing/` (요구사항) | 단가·마진 구조, 규격(두께·손질)·납기 정의, 주문 자동화 요구사항 |
| **김정민** | UX · CS 응대 설계 | `docs/cs-routing.md`, `docs/screens.md` | 3면 화면 흐름, 답변 톤·에스컬레이션 기준, 사용자 시나리오 |
| **임세준** | 브랜드 · 콘텐츠 | `docs/brand.md`, `app/static/` | 마스코트·톤앤매너, SNS 카피, B2C 입문자 큐레이션 기준 |

### 역할 경계

- **김정민 ↔ 임세준**: 같은 화면을 두고 겹치면 이 기준으로 자른다.
  김정민은 **구조와 흐름**(무엇이 어디에, 어떤 순서로), 임세준은 **표현과 톤**(어떤 말투, 어떤 그림).
- **박경환 ↔ 개발**: 박경환은 "무엇이 필요한가"(요구사항)까지, 구현 방식은 류현수·조윤빈이 정한다.
- 담당 경로 밖의 파일은 오너에게 이슈로 요청한다. 직접 고치지 않는다.

### 협업 규칙 (설계 단계)

- 모든 산출물은 `docs/` 에 마크다운으로. 각 파일 맨 위에 담당자 이름 한 줄.
- 리뷰는 **류현수 1인 승인제**. 설계 단계에서 전원 합의를 요구하면 진도가 나가지 않는다.
- 주 1회 30분, 각자 `docs/` 변경분만 공유. 회의록은 남기지 않되
  "왜 그렇게 정했는지"는 `docs/decisions/` 에 기록한다.

### 인원 제약

구현 가능 인원이 류현수·조윤빈 2명뿐이므로, 코드 단계 진입 시
CS 챗봇 1개만 먼저 동작시키고 나머지 면은 화면 스케치로 대체한다.
